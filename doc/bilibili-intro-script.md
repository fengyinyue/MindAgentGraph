## 简介（视频描述栏）

MindAgentGraph 是一个可视化节点规划工具，把 AI 的工作组织成有向图（DAG）——每个节点有独立的任务目标、文件权限和上下文范围，节点之间通过边传递数据。本期视频介绍项目核心理念，并演示「游戏开发工作流」模版，从一句创意出发，自动拆解出需求分析、架构设计、代码实现、运行验证全流程。

### 【开场白 | 0:00-1:30】

大家好，我是 [名字]。

做过复杂项目的人可能都有这种经历——

你打开 Claude 或者 ChatGPT，开始聊项目。
前十轮还挺顺，AI 理解你的意图，给出不错的回答。
然后上下文越来越长，AI 开始"失忆"，你的问题和代码混在一起，根本看不清项目进展到哪了。

更麻烦的是：AI 不知道自己该管哪些文件、不该碰哪些文件。你让它改个功能，它顺手动了你不想动的地方。

还有一个问题——**长期项目没有结构**。一个月后你回来继续，聊天记录已经成了一堆信息噪音，没法复用，没法接着上次的思路跑。

这三个问题，就是我做 **MindAgentGraph** 的原因。

---

### 【项目介绍 | 1:30-3:00】

MindAgentGraph 是一个**节点式 AI 规划工具**。

它的核心思路很简单：**不要用聊天组织 AI 的工作，用图来组织。**

你在一块无限画布上画节点，每个节点就是一个独立的任务——比如"需求分析"、"架构设计"、"代码实现"。节点之间用边连接，表示"这个节点的输出是下一个节点的输入"。

每个节点都有自己的：
- **目标（purpose）**：这个节点要做什么
- **文件权限（file scope）**：只能看哪些文件，绝不越界
- **上下文模式**：是继承上游节点的输出，还是独立运行

图既是你的**项目规划**，也是 AI 的**执行仪表盘**。

技术栈是 React + FastAPI + Tauri，支持 Claude、DeepSeek、OpenAI 多种模型，项目存储为 `.mag` 文件夹，纯 JSON，Git 友好。

今天我们用一个具体的例子来演示——**游戏开发工作流模版**。

---

### 【加载模版 | 3:00-5:00】

打开应用，左边是项目列表。

我这里有一个叫 `game-dev` 的模版，描述是「游戏开发工作流：从创意到可运行游戏」。

点进去，画布上出现了 7 个节点——这就是一个完整的游戏开发流水线。

我们从左往右看一遍整体结构：

```
游戏创意  →  需求分析  →  环境初始化
                    ↘
                      架构设计   →  功能实现  →  运行验证
                                          ↘          ↓
                                            →  代码审查
```

可以看到，需求分析之后有两条并行的路：一边去初始化项目环境，一边做架构设计。两条路的结果汇聚到"功能实现"节点，再往后是验证和审查。

这个图的拓扑结构，就已经把游戏开发的依赖关系说清楚了——架构要等需求，代码要等架构和环境都准备好。

---

### 【逐节点讲解 | 5:00-11:00】

**节点一：游戏创意（Prompt 节点）**

这是整个工作流的起点，是个 `prompt` 类型的节点，里面存着一段话：

> "使用 Python 和 Pygame 开发一个经典贪吃蛇游戏，采用面向对象设计，包含蛇移动、食物随机生成、碰撞检测、计分、游戏结束与重新开始等完整功能，代码结构清晰、易于扩展。"

就这一句话，它的输出会通过边流向下游所有节点，作为整个图的原始上下文。

---

**节点二：需求分析（Planning 节点）**

这是个 `planning` 类型节点，目标是：明确游戏类型、核心玩法机制、操控方式、画面规格与胜负条件。

它有一个输入：来自"游戏创意"的文本；有一个输出：需求文档。

我们已经跑过这个节点了，可以看它的输出——AI 生成了一份非常完整的需求文档，涵盖了游戏类型、玩法机制、键盘操控、画面规格、胜负条件，甚至还规划了面向对象设计的类结构。

用了 DeepSeek v4 Flash，11 秒出结果。

---

**节点三：环境初始化（Code 节点）**

`code` 类型节点，负责创建项目目录、配置 `pyproject.toml`、安装 pygame 依赖。

注意这个节点的文件权限设置——`fileScope.allow` 只允许访问 `pyproject.toml`、`.python-version`、`src/**`、`.gitignore`，其他文件它碰不到。这就是 MindAgentGraph 的文件隔离机制，**AI 只在授权范围内操作**。

---

**节点四：架构设计（Planning 节点）**

这个节点和环境初始化并行运行，也等着需求文档。

它的任务是设计类结构、主循环流程、状态机（菜单/游戏中/结束）与模块划分。

已有输出，来看看——AI 设计了完整的模块划分表（config、entities、states、manager、input、render、main 七个模块），画出了状态机的转换图，还有类间关系树，主循环的伪代码，每个设计决策都说明了理由。

---

**节点五：功能实现（Code 节点）**

这是执行量最大的节点。

它等待两个上游：项目骨架 + 架构方案。两个都准备好了，才开始运行。

文件权限只允许访问 `src/**` 和 `assets/**`，不会碰项目其他部分。

这个节点会调用 Claude Code 来实际写代码，工具权限开放了 bash、read_file、write_file。

---

**节点六：运行验证（Code 节点）**

代码写完，这个节点做语法检查和静态扫描，用 `python -c` 验证可运行性，输出一份验证报告。

---

**节点七：代码审查（Code 节点）**

最后一站。

它同时接收"游戏代码"和"验证报告"两个输入，审查碰撞检测逻辑、边界处理、帧率控制、状态管理完整性，给出优化和扩展建议。

---

这 7 个节点，就把一个完整的游戏开发流程，从创意到可运行代码，全部结构化了。

---

### 【运行演示 | 11:00-13:30】

现在我们实际跑一下。

点击"需求分析"节点，右侧面板可以看到节点配置。点顶部的运行按钮，底部监控面板开始出现 SSE 流式输出，token 用量实时更新。

---（此处录屏演示）---

可以看到，AI 正在逐步输出需求文档，是真实的流式响应，不是假进度条。

节点完成后，状态变成绿色的"done"。

然后我们点"架构设计"节点跑一下——它会自动继承需求分析的输出作为上下文，不需要你手动复制粘贴。

### 【总结 | 13:30-】

MindAgentGraph 现在处于早期阶段，核心功能已经可以跑起来：

- 可视化节点画布，支持手动搭工作流
- 一句话自动生成 DAG
- Planning 节点 + Code 节点的混合执行
- 文件权限隔离
- 多模型支持

接下来我想做的方向是：**把 Claude Code 的 tool 执行能力固化成可复用的节点子图**，做到"录制一次，任意重放"——这样每个工作流模版就真正有了确定性的执行能力。
